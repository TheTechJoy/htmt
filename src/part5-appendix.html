Appendix A. RELAX NG Schema (normative)

The schema is given in RELAX NG compact syntax [RNC] and is distributed as htmt-1.0.rnc. It is the normative definition of content models and attribute lexical types. It does not express the integrity rules of 13.1 (items 3–7); the reference validator (tools/validate.py) checks both. An equivalent schema in RELAX NG XML syntax is distributed as htmt-1.0.rng for tools that do not read the compact syntax; where the two differ, htmt-1.0.rnc governs.

Appendix B. Grammar (normative)

Lexical forms in ABNF [RFC 5234]. These are equivalent to the datatype facets in Appendix A; the schema governs if the two are ever found to differ.

clock-time   = hours ":" minutes ":" seconds [ "." fraction ]
hours        = 1*DIGIT                 ; unbounded, zero-padding optional
minutes      = %x30-35 DIGIT           ; 00-59
seconds      = %x30-35 DIGIT           ; 00-59
fraction     = 1*6DIGIT

token        = LALPHA *( LALPHA / DIGIT ) *( "-" 1*( LALPHA / DIGIT ) )
LALPHA       = %x61-7A                 ; a-z

id           = NCName                  ; [XML-NAMES] section 3
idref        = NCName

confidence   = "0" [ "." 1*DIGIT ] / "1" [ "." 1*"0" ] / "." 1*DIGIT

datetime     = date-time               ; [RFC 3339] section 5.6, offset SHOULD be present
date         = full-date / date-time   ; [RFC 3339] section 5.6

uri          = IRI-reference           ; [RFC 3987]
internal-ref = "#" id                  ; fragment-only URI addressing a local id

Appendix C. Well-Known Event Types (normative)

Producers SHOULD use these tokens for the occurrences they describe and MAY use any other token. Processors MUST tolerate unknown types. New well-known types may be added in minor revisions.

TypeMeaningTypical attributes / content
silenceNo speech for a notable interval.start, duration
inaudibleSpeech occurred but could not be transcribed.start, end, speaker
crosstalkMultiple speakers overlapping such that attribution failed.start, end
laughter, applause, musicNon-speech audio.start, optional speaker
join, leaveA participant entered or left the conversation.speaker required, start or datetime
recording-start, recording-stopRecording boundaries, where the conversation extends beyond the recording.start, media
screen-shareVisual content was shared.speaker, start, end; content describes what was shown, optionally with <ref>
file-sharedA file or link was posted into the conversation.speaker; content SHOULD contain a <ref>
reactionA lightweight non-verbal response (emoji, thumbs-up, hand raise).speaker; content is the reaction
tool-call, tool-resultAn agent invoked a tool / received its result (Section 11).speaker (the agent); payload in an extension namespace
systemA message injected by the hosting platform rather than any participant.content is the message text

Appendix D. Changes from the Conceptual Draft (informative)

The conceptual draft described intent but left syntax under-specified. This final specification resolves each open point. Documents written to the draft's examples need the following adjustments.
